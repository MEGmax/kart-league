# Night Kart League

React + MUI site (repo MEGmax/kart-league, branch `main`), built with Vite and deployed to GitHub Pages
by `.github/workflows/deploy.yml` (push to `main` triggers a build and a GitHub Actions Pages deploy — Pages
must be set to "GitHub Actions" in repo settings, not "Deploy from a branch"). Source lives under `src/`;
`vite.config.js` sets `base: "/kart-league/"` to match the Pages URL. Run `npm install` then `npm run dev`
locally (needs Node 20+; this repo was scaffolded and built with Node 24 via nvm since the system default
was Node 16). Character art is served as static files from `public/assets/characters/`. Track pictures (16:9 WebP, one per track in `TRACKS`) are in `public/assets/tracks/`, made by `tools/tracks.py` from the Super Mario Wiki's Mario Kart Wii course images (sources in `data/track-sources.json`); `trackSrc()` in `constants.js` and `TrackImage` (`src/components/TrackImage.jsx`, placeholder for custom tracks) show them on Join, Schedule, the vote, the cup builder, track pickers, the racer drawer and the profile.

Accounts and data are in Supabase (Auth: email/password only — Google sign-in was removed from the site; Postgres with row level security). The
project URL and publishable key live in `src/lib/supabaseClient.js` — safe to publish; access is enforced
by RLS in `supabase/schema.sql`. The client is `@supabase/supabase-js@2.118.0` via npm (not a CDN import).

## Frontend structure

- `src/context/AuthContext.jsx` — session, profile, role helpers (`isAdmin`, `isOwner`), sign in/up/out, password reset/update.
- `src/context/LeagueDataContext.jsx` — loads `league`/`players`/`cups`/`race_results`/`cup_templates`/`events` (+ `event_attendees()`) and subscribes to Postgres realtime changes.
- `src/lib/standings.js` — `normalize()`/`compute()`, ported 1:1 from the old `app.js`. Pure functions; standings math lives only here. `compute(st, { season })` shows one season (default `currentSeason()`; `"all"` for pages that look cups up by id: Layout's unclaimed count, Unclaimed, Admin, Schedule, TrackVote) and ranks it by `rankByFor(league, season)`: `"rating"` (skill rating, the default and the headline number everywhere: standings, podium, profile, drawer, playoffs, member cards; `seasonRatings()` carries last season over) or `"pct"` (points percentage, when `league.settings.rankBy` is `"pct"` or a past season's `seasonRankBy` says so). Rating mode also needs `provisionalCups` cups to qualify (`m.minCups`); rows get `rating`, `ratingDelta`, `provisional`, `form`, `consistency`, `overUnder`, `closer`, `comebacks`, `top3Rate`, `attendance`, `upsets`, `lastAmongHumans`.
- `src/lib/rating.js` — the Elo-style rating (`rateSeason`, `matchScore`, `upsets`); formula and settings are on the Rules page. Cups in weeks after `seasonWeeks` (playoffs) don't move ratings. `src/lib/rivals.js` (head-to-head, rivalry of the season, nemesis/favourite) and `src/lib/records.js` (records, the 10 awards) are used by the racer drawer (nemesis/favourite) and the Stats page; `records.js` awards, `rivalry()` and `leagueTracks()` in `tracks.js` (track table, chaos index, coverage) are tested but no page shows them now. Tests use the real Season 1 cups in `tests/fixtures/season1.json` (`rating-lib`, `rivals-lib`, `records-lib`, `standings-lib`). `SeasonPicker`/`useSeason` (`?season=N`) is on Schedule and Stats; Admin › League settings has the rating keys and **Start Season N** (bumps `currentSeason`, records the old season's `rankBy` in `seasonRankBy`).
- `src/lib/demo.js` — the example/demo season shown when a league has no real cups yet.
- `src/pages/` — one component per nav tab, routed with `react-router-dom`'s `HashRouter` (so GitHub Pages needs no server-side rewrite rules; the old `#/events`, `#/race`, `#/cups`, `#/history`, `#/rivals` and `#/records` links redirect, keeping `?season`): `StandingsPage` (the **Home** tab, still at `#/standings`; its `Hero` has a decorative Mario kart, `KartRacer`, driving along the bottom stripe, parked for reduced motion), `SchedulePage` (the **Schedule** tab, `#/schedule`, `#/schedule/:id`, which merged the old History page: upcoming nights as `EventCard` rows, then every night raced this season, newest first, each with its cups' results in `CupCard` (`src/components/CupCard.jsx`; the season's newest cup is shown big with track pictures); `SeasonStrip` sticks under the header with the season's cups as pips grouped by night (raced, planned, not scheduled yet), underlines the night on screen and scrolls to a night when tapped), `UnsubscribePage`, `RaceNightPage` (**Join**, `#/join`), `StatsPage` (**Stats**, `#/stats`: season leaderboards. Cup wins and points a cup (3+ cups) lead as the two big boards (top 5); then top 3 finishes, race wins, longest win streak, best cup, best head-to-head (3+ cups together), cups raced and last places (of the league's racers), top 3 each, ties sharing a place. A signed-in racer's own row is highlighted, and added under a board they're not in the top of. Rows open the racer drawer. Numbers come from `playerSheet()`/`leaderboard()` in `src/lib/playerStats.js` (pure, tested in `tests/player-stats-lib.test.js`); the old `#/rivals` and `#/records` pages were folded in and redirect here), `AddPage`, `BuildPage`, `UnclaimedPage`, `PlayoffsPage`, `RulesPage`, `AdminPage` (admin tab shown to admins only) and `AccountPage`.
- `AddPage` (`#/add`) records a whole cup night: specific cups (game cups/templates/custom tracks, or `UNKNOWN_CUP` "Unknown Cup" with no tracks for random tracks nobody remembers), each racer's usual character (a cell's `character` overrides it for one cup; picking a player already in the lineup for a racer who never shared a cup with them merges the two via `mergeRacers`), and per-cup totals or race-by-race places. Modes: admin save (`save_cup_night`), member submit (one `submit_cup` per cup sharing `submissions.batch`), admin review (`?review=<batch>`), edit one finished cup (`?edit=<cupId>`), start from a cup night (`?event=<id>`). Logic lives in `src/lib/night.js` (pure, tested in `tests/night-lib.test.js`); UI pieces in `src/components/night/`.
- `UploadPage` (`#/upload`, admins) is the fast way to record a night: pick every cup's end-of-cup photo at once (`PhotoPickButton` on Join and Add opens the picker and hands the files over via `src/lib/handoff.js`). Each photo is read with Gemini (2 at a time, retrying on 429), ordered by EXIF capture time (`src/lib/photoTime.js` runs `scripts/lib/exif.js` in the browser), grouped into cups and matched to players by `nightFromPhotos()` in `src/lib/upload.js` (pure, tested in `tests/upload-lib.test.js`; reuses `groupBacklog`/`nightFromBacklog`, plus a name on screen that matches a player). The league plays VS mode, whose end-of-cup screen shows no course, so tracks can't be read from photos: every cup starts as Unknown Cup and the check screen lets the admin pick a game/saved cup or "the 4 tracks we picked". It warns when a cup on that date already has the same points (`alreadySaved`). Saving goes through `saveNightAsAdmin()` (`src/lib/saveNight.js`, shared with the Add page), so standings update live; **Edit in the full form** hands the night to the Add page. Reading photos with Gemini (the key on the Account page, Upload, Add's per-cup read, Join's finish check) is admins-only.
- `src/lib/gemini.js` — reads a results photo with Gemini (`gemini-4-hydrogen`; plain `fetch` to `generateContent` with `responseJsonSchema` and high media resolution, no SDK) so the same code runs in the browser and in Node. Returns `{screen: race|standings|other, cup, rows: [{pos, name, character, points (total), gained (+N), human, highlight}]}`. `src/lib/readPhoto.js` wraps it for the site with the visitor's own key (`localStorage` `kl.geminiKey`, set on the Account page); used by the Add page and Join's Finish panel, where rows are matched to racers by character, then name (`matchPhotoRows`).
- `npm run backlog -- <folder>` (`scripts/read-backlog.mjs`, run with vite-node so it can import `src/lib`) reads a folder of a night's photos with `GEMINI_API_KEY` from `.env`: EXIF order (`scripts/lib/exif.js`), HEIC converted with macOS `sips` (cup photos turned upright by `--rotate`, else Gemini's unreliable `rotate` guess), skips images without camera info (screenshots) unless `--include-screenshots`, caches readings in `<folder>/gemini-reads.json`, and writes `backlog.md` plus `backlog-import.json` (git-ignored, includes photos). `src/lib/backlog.js` (pure, tested in `tests/backlog-lib.test.js`) groups photos into cups by running totals (an end-of-cup screen closes a cup once its race count is 4 or unknown), keys humans by character (plus highlight color when two share one), derives race places from the change in totals checked against `+N`, names cups "Unknown Cup", and `nightFromBacklog()` turns the file into an Add-page night (**Import a backlog file** button); `--who Luigi=Gerrard` names who played a character, otherwise players are guessed from their most-picked character.
- `src/lib/accountData.js` — `useMyData()` (your claims/submissions) and `useAdminData()`; both refetch when `LeagueDataContext`'s `version` bumps after a realtime reload.
- `src/lib/events.js` — cup night helpers (upcoming/past split, "Cup TBD", local time formatting). `LeagueDataContext` exposes `events` (with `going` attendee lists).
- `src/lib/standings.js` also has `seasonPlan()` (the one source for weeks, cups raced/total/to go and the current week; a week that ran over counts its extra cups) and `playerSlug`/`playerFromSlug` for racer links (`#/standings/<name>`, opened in `RacerDrawer`). Character stats are per race (a totals-only cup counts as its 4 races); "cup wins" and "race wins" are separate fields everywhere. `CHARACTER_COLORS`/`charColor()` in `constants.js` give each character one color.
- Profiles have up to 3 `favorite_tracks` (v8 column; the Account page sends it only when changed so the rest of a profile saves before the schema is re-run), shown in the profile's Favourite tracks section with "Where you score best" from `bestTracks()`.
- Track voting (v7): racers who are in for the next cup night suggest/vote on up to 8 tracks each (`event_track_votes`, written only through `vote_track`/`unvote_track`; `leave_event` drops your votes; members-only `track_vote_tally()`). `src/components/TrackVote.jsx` on Join shows the ballot grouped 4 per cup plus your best tracks from `bestTracks()` in `src/lib/tracks.js` (pure, tested in `tests/tracks-lib.test.js`; per race points, totals-only cups count at their per-race average); `src/lib/trackVotes.js` is the data hook. The cup builder's **Use the top 4** fills the tracks from the vote, skipping tracks already raced on that date. DB tests: `tests/track-votes-db.test.js`.
- `src/lib/events.js` `pastNights()` builds past cup nights from the cups actually raced, by date in the league's time zone (`league.settings.timezone`), including dates nobody scheduled.
- `src/components/Layout.jsx` — top tabs on desktop, a bottom tab bar (+ More menu) on phones; `PullToRefresh` (touch only) reloads the league data in place via `LeagueDataContext`'s `refresh()` (the theme turns off the browser's own overscroll/pull-to-refresh); scrolls to the top when the section changes; `src/lib/pageMeta.js` sets each route's title/description. Pages other than Standings are lazy-loaded (`App.jsx`); `vite.config.js` splits MUI/React/Supabase into their own chunks. Link previews use the static Open Graph tags in `index.html` (`public/brand/og-image.png`).
- `src/theme.js` — the MUI dark theme, following `DESIGN.md` (the design brief: type scale, colour tokens and what each means, when a border is allowed, how a table row looks). One flat navy page (`colors.bg`), two fonts (Rubik Mono One for the wordmark and page titles only; Barlow with tabular figures for everything else), colour only with meaning (gold = leader/1st and the primary button, red = the playoff line and errors, green/red = rating up/down, silver/bronze on the Home podium only; player colours are stored but not drawn). Content sits on the page grouped by spacing and hairlines, not in bordered panels. `brandStripe` is the logo's navy|white|red split, used as trim.
- Branding: the source logo is `data/nkllogo1.png`; `public/brand/nkl-logo.png`, `public/favicon.png` and `public/apple-touch-icon.png` are resized from it. Components use `LOGO_SRC` from `src/lib/constants.js` (header, standings hero, footer, sign-in). `PageTitle` (display face), `SectionTitle`, and `Fact`/`FactList` (a plain label over one bold fact, used instead of stat tiles) are in `src/components/PageBits.jsx`.

## Database

`supabase/schema.sql` is the single source of truth: tables (`league`, `players`, `cups`, `photos`, `profiles`, `submissions`, `submission_photos`, `player_invites`, `claims`, `cup_templates`, `race_results`, `events`, `event_commitments`, `event_track_votes`, `email_tokens`, `email_outbox`), RLS policies, and `security definer` functions that re-check roles (`create_cup`, `enter_race`, `clear_race`, `finish_cup`, `reopen_cup`, `my_player_id`, `save_cup`, `submit_cup`, `reject_submission`, `save_settings`, `save_players`, `approve_claim`, `reject_claim`, `set_role`, `save_cup_night`, `claim_ownership`, `delete_my_account`, `create_event`, `update_event`, `cancel_event`, `join_event`, `leave_event`, `event_attendees`, `vote_track`, `unvote_track`, `track_vote_tally`, `league_members` (v9: confirmed accounts' display name, color, role, favourites, join date and linked player for signed-in members; never emails), `unsubscribe_email`, `current_season` (v10); service role only: `queue_event_reminders`, `claim_emails`, `complete_email`). Upgrades to existing tables use `alter table ... add column if not exists` so the file can be re-run on the live database. It is written to be re-runnable. After editing it, the user must paste it into Supabase › SQL Editor and run it; there is no CLI deploy for the schema (only the Edge Functions use the CLI).

Roles are in `profiles.role`: member, admin, owner (exactly one, claimed once).

Privacy (schema "v6" sections): signed-out visitors (`anon`) can read only the columns the public pages show (column grants on `players`, `cups`, `race_results`, `cup_templates`, `events`: no `user_id`/`added_by`/`entered_by`/`created_by`), nothing from `event_commitments` or `photos`, and can write nothing; `event_attendees()` returns `user_id` only to signed-in callers. So the client must never `select("*")` on those tables: `LeagueDataContext` names its columns (`COLS`) and fetches `players.user_id` separately when signed in. Results photos are for signed-in members only: they live in the private Storage bucket `cup-photos` (admins write) as `cups/<cup id>/<version>.jpg` (≤1600px) plus `-thumb.jpg` (600px wide), with `cups.photo_path` holding the full-size path; `src/lib/cupPhotos.js` re-encodes every photo on a canvas before upload, which strips EXIF/GPS. The old `photos` table (base64 text, members-only now) is legacy: Admin › Results photos moves its rows to Storage. The repo is public, so photos committed under `data/` must have no GPS: `npm run strip-gps -- <folder>` (lossless for JPEG, keeps capture time) and the backlog script warns.

- `cups.results` is a JSON array of `{rid, p, pts, character, raw}`. `p: null` means unclaimed (a human row not yet tied to a player); unclaimed rows still count in the cup's finishing order. `rid` is stable and claims point at it.
- `cups.status` is `racing` (built, results being entered on Race night) or `complete` (counts in standings). `cups.maps` holds the 4 tracks and is locked by the `cups_lock_maps` trigger once set. `race_results` has one row per player per race (position 1-12, points from `race_points()`); members write only through `enter_race`/`clear_race`. `finish_cup` builds `cups.results` from them.
- `save_cup_night(p_cups, p_players)` (admins) saves several finished cups in one transaction: creates new players, upserts each cup (`complete`; existing tracks and `added_at` are kept), replaces its `race_results` when a cup has a `races` key (rejecting shared places and race points that don't add up to the totals), and approves the cup's `submission` if given. Photos are upserted into `photos` afterwards by the client. `finish_cup` keeps a reopened cup's existing unclaimed rows.
- `cups.week` is the season week. League settings (`league.settings`) include `seasonWeeks` and `cupsPerWeek`.
- `cups.season` / `submissions.season` (v10): `create_cup`, `submit_cup`, `save_cup_night` and `save_cup` set it from `current_season()` (`league.settings.currentSeason`, default 1) on insert; editing a cup keeps its season, and approving a submission uses the submission's season. Rating settings keys: `rankBy`, `ratingStart`, `ratingK`, `ratingKProvisional`, `provisionalCups`, `marginCap`, `carryOver`, `playoffCupsPerRound`, `seasonRankBy` (defaults in `DEFAULT_LEAGUE`).
- `players.user_id` links a player to an account; `registered_at` drives the "Joined" badge. `player_invites` (admins only) holds an email that auto-links on email confirmation via the `on_auth_user_confirmed` trigger.

- `events.cups` is a text array of cup names in order; empty = "Cup TBD". `events.sequence` is the .ics SEQUENCE (bumped on date/time or cup changes and on cancel); the .ics UID is `cup-night-<id>@kart-league`. Cancelling is a soft cancel (`status = 'cancelled'`).
- Cup night emails go through `email_outbox` (unique per event/user/kind/sequence), drained by the `send-emails` Edge Function via pg_cron; `profiles.email_cup_nights` is the opt-in. Edge Functions are deployed with `npx supabase functions deploy` (see README › Cup night emails). Emails are log-only until a Resend domain is set up. `league.settings` also holds `timezone` and `reminderHour`; `save_settings` replaces the whole settings object, so an admin settings form must keep those keys.

`npm test` runs Vitest: `tests/events-db.test.js` loads `schema.sql` into PGlite via `scripts/lib/localdb.js` (stubs for auth, roles and realtime) and exercises each role. To test other schema changes locally, run it in PGlite (`@electric-sql/pglite`, Node 20+) with stubs for `auth.users`, `auth.uid()` (reading `request.jwt.claim.sub`), the `anon`/`authenticated` roles and the `supabase_realtime` publication, then exercise each role with `set role`.

## When the user shares a results-screen photo

Claude Code has no database credentials, so it cannot write cups directly. Read the photo (highlighted rows are humans; for each, the character and points; skip unhighlighted CPU rows), then give the user a table of league players and points to enter on the site's **+ Add cup** page. For a whole folder of a night's photos, run `npm run backlog -- <folder>` and have the user import `backlog-import.json` on the Add page.

## Rules of the data

- `max` is points possible per player for that cup (60 for a standard 4-race cup with 12 racers).
- Standings are computed in `src/lib/standings.js` (`compute`); never store derived numbers.
